# 图像节点图预览（WebGL2）

上传 PNG，连接 **输入 / 颜色矩阵 / 模糊 / 混合 / 上一帧** 节点，逐帧预览并导出 PNG。
内部管线为 **线性 RGB + 预乘 alpha**，导出时转换回普通 sRGB PNG。纯本地运行，不依赖任何云端图像服务。

## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

### 本地开发（Node ≥ 18）

```bash
npm install
npm run build     # 编译 client/src -> client/dist
npm start         # http://localhost:8080
npm test          # 图校验纯逻辑单元测试（14 例）
```

健康检查：`GET /api/health` 返回 `{"ok":true,...}`。

## 验证步骤

1. **半透明反馈示例**：打开页面即自动加载（或点「半透明反馈」）。运行中可看到半透明图形
   逐帧累积出残影，棋盘格表示半透明区域；帧号持续增长。首帧时「上一帧」输出透明。
2. **上传 PNG**：点击输入节点的「选择 PNG…」。图像按 sRGB 解码到线性空间并预乘。
3. **暂停 / 单步 / 导出 / 继续**：共用同一帧编号。导出文件名为 `frame-XXXX-rN.png`，
   内容为当前显示帧的普通 sRGB PNG（直出 alpha）。
4. **循环拒绝示例**：点「循环拒绝」，底部红条显示同帧循环依赖错误，**旧修订继续运行**
   （修订号不变、帧号不归零）。点「放弃草稿」回到活动修订。
5. **修订语义**：任意修改（连线、参数、尺寸、上传）都会把草稿作为完整候选验证；
   成功后修订号 +1 并从第 0 帧重启；失败保留旧图。
6. **上下文丢失**：点「模拟上下文丢失」→ 出现黄色横幅，画面冻结、帧号不变；
   点「恢复上下文」→ 资源重建，从最近完成帧继续，反馈不重复推进（残影状态保持）。
7. **资源释放**：删除节点（节点头 ×）后，HUD 中「纹理池 在用/空闲 · 反馈 · 输入」
   计数随即反映释放；空闲纹理保留在池中供后续帧复用。
8. **遍历顺序无关**：同一反馈图无论如何拖动/增删节点，同帧号的画面一致
   （拓扑序确定，且反馈统一在帧尾换页）。

## 设计说明

### 颜色管线
- 输入 PNG 以 `SRGB8_ALPHA8` 上传，采样时硬件解码 sRGB→线性，着色器内完成预乘。
- 所有中间纹理为 `RGBA8`（线性、预乘）。颜色矩阵作用于预乘向量，RGB 偏移项乘 alpha
  以保持预乘不变式；模糊直接滤波预乘值；混合（over/add/multiply/screen）全部按
  预乘合成公式计算。
- 预览与导出着色器做 解预乘 + 线性→sRGB（精确分段曲线）；预览叠加棋盘格显示半透明，
  导出走 `readPixels` → `canvas.toBlob('image/png')`。

### 反馈与纹理
- **同帧无环**：指向「上一帧」节点的边是跨帧反馈边，不参与同帧拓扑排序；其余边构成
  的图必须无环，否则候选被拒绝。拓扑排序按 id 有序取点，结果确定。
- **反馈双缓冲**：每个「上一帧」节点持有历史纹理，帧内只读；帧尾把反馈源拷贝到一张
  新纹理并换页，旧纹理归还纹理池。所有反馈因此同时读到“上一完整帧”，与遍历顺序无关。
- **纹理复用**：节点输出与模糊中间纹理取自按尺寸分桶的纹理池，帧尾统一归还；
  任何一次绘制都不会读写同一纹理（模糊两趟经中间纹理，拷贝总是异纹理）。
- **资源释放**：切换到新修订时，旧修订独占的历史纹理/显示纹理归还池中，被移除节点的
  输入纹理直接删除；尺寸变化时纹理池整体清空重建。

### 修订与异步
- 编辑产生的是**草稿**；每次修改把草稿整体克隆为候选，先完整验证（结构、环、尺寸），
  通过才原子换入引擎并从第 0 帧启用；失败保留旧修订继续运行。
- 上传/示例图像的异步解码用「节点令牌 + 草稿代次」防护：过期回调直接丢弃，
  不会覆盖新修订；导出的像素在点击瞬间同步捕获，`toBlob` 回调只下载自己的快照。
- 暂停、单步、导出、继续都使用同一帧计数器（`lastFrame`/`frame`）。

### 上下文丢失
- 「模拟上下文丢失」调用 `WEBGL_lose_context.loseContext()`；每帧结束已把历史纹理与
  显示纹理 `readPixels` 到 CPU 快照，恢复后据此重建全部 GL 资源（程序、纹理池、
  输入纹理、反馈历史、显示纹理），帧号不回退、反馈不重复推进。
- 代价：存在反馈节点时每帧有 1–2 次 1–4MB 的读回（预览尺寸下可接受）。

## 目录结构

```
client/src/graph.ts    图数据结构 + 校验（纯逻辑，可单测）
client/src/shaders.ts  全部 GLSL（线性/预乘管线）
client/src/engine.ts   WebGL2 引擎：纹理池、反馈双缓冲、上下文恢复
client/src/editor.ts   节点编辑器（DOM+SVG）
client/src/examples.ts 内置示例（半透明反馈 / 基础链 / 循环拒绝）+ 程序化演示图
client/src/main.ts     装配：草稿->候选->原子提交、播放控制、导出
server/server.js       零依赖静态服务器（/api/health）
test/graph.test.mjs    校验逻辑单元测试
```
