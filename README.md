# 图像节点图预览（TypeScript + WebGL2）

上传 PNG，连接 **输入 / 颜色矩阵 / 高斯模糊 / 混合 / 上一帧** 节点，逐帧预览并导出 PNG。
内部一律使用 **线性 RGB + 预乘 alpha**（优先 `RGBA16F`，无 `EXT_color_buffer_float` 时回退 `RGBA8`），
显示与导出时转换回普通 sRGB PNG。纯本地运行，不依赖任何云端图像服务。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8080
```

本地开发（可选）：`npm install && npm run build && npm start`。

## 界面速览

- 顶栏：暂停/继续、单步、导出 PNG、模拟/恢复上下文丢失、两个示例、画布尺寸。
- 状态栏（右上）：**当前修订号、帧号**、运行状态、像素格式、存活 GPU 纹理数。
- 左侧：添加节点、候选验证错误列表、节点卡片（参数、输入槽下拉、节点级错误、输出/预览/删除）。
- 节点间连线：灰色实线为同帧依赖，**橙色虚线为反馈边**（「上一帧」节点）。

## 验证步骤

1. **基本链路**：打开页面即载入「半透明反馈」示例（输入 → 混合 ← 衰减 ← 模糊 ← 上一帧）。
   点击任意节点的「预览」查看其输出；棋盘格背景用于观察半透明。
2. **上传 PNG**：在「输入图像」节点选择本地 PNG。上传解码是异步的，带序号保护——
   连续选择两张图，只有后一张生效，旧回调不会覆盖新结果。
3. **逐帧 / 暂停 / 单步 / 导出**：帧号是唯一计数。暂停后「单步」恰好 +1 帧；
   「导出 PNG」导出当前帧（文件名含修订号与帧号，如 `graph-r3-f41.png`），
   导出先同步读回像素再异步编码，期间改图不影响本次导出；「继续」从同一帧号继续。
4. **线性空间验证**：对输入做模糊/混合后导出，PNG 为普通 sRGB；
   内部线性 + 预乘 alpha 可在半透明边缘看到无黑边的正确混合。
5. **反馈与首帧**：示例中「上一帧」读取混合节点的上一完整帧，形成拖影；
   第 0 帧反馈读取透明图（无残影）。所有反馈经 ping/pong 双缓冲读取上一完整帧，
   同一次绘制绝不读写同一纹理，结果与节点遍历顺序无关。
6. **循环拒绝**：点击「示例：循环依赖（应被拒绝）」——候选含同帧环，
   验证失败并列出错误，**旧修订继续运行**（状态栏修订号不变）。
7. **修订语义**：每次有效修改（含尺寸）都会整体验证候选，成功后修订号 +1 并从第 0 帧启用；
   失败则保留旧图可用状态。
8. **上下文丢失**：点「模拟上下文丢失」（画面冻结、状态栏提示），运行一段时间后点「恢复上下文」——
   资源重建并**确定性重放**到最近完成帧，帧号连续、反馈不重复推进（可对照帧号与画面验证）。
9. **资源释放**：删除节点或改图时，旧修订的纹理/FBO 全部销毁；
   状态栏「GPU 纹理」计数与控制台日志（`[gpu] 已释放修订 #N 的资源`）可验证。

## 设计要点

- **双缓冲反馈**：被「上一帧」引用的节点持有两张纹理，渲染第 N 帧只写 `tex[N%2]`、
  只读 `tex[(N-1)%2]`；纹理创建时清零，保证首帧反馈为透明。
- **纹理复用**：模糊等中间结果取自按尺寸复用的纹理池，随修订统一释放。
- **候选验证**：尺寸、连接完整性、参数范围、同帧无环（Kahn 拓扑，反馈边除外）全部通过才提交。
- **恢复策略**：上下文恢复后重建程序/纹理，重放 `0..completedFrames-1` 帧恢复反馈状态，
  计数器保持不变。
- **异步安全**：上传带单调序号；导出同步取像素；旧修订的回调不会覆盖新结果。

## 目录

```
src/graph.ts   图模型与候选验证（环检测、拓扑序）
src/gpu.ts     WebGL2 引擎（着色器、双缓冲、纹理池、导出）
src/app.ts     编排与 UI（修订、帧循环、上下文恢复、上传）
server/        零依赖静态服务（仅服务本地 public/）
public/        页面与样式（app.js 由构建生成）
```
